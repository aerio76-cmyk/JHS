## 2. 遷移 SQL 與規劃書草稿的差異
| 項目 | 草稿 | 實作 | 原因 |
|---|---|---|---|
| Storage 的 select 政策 | 公開讀取 | **只開給白名單** | public bucket 的公開網址本來就不經過 RLS；開放 select 會讓任何人透過 API 列出所有檔名。**前台只能用 `getPublicUrl()`** |
| 重複執行 | `create policy` 會報錯 | 先 `drop policy if exists`；限制也先 drop 再 add | 可以安全重跑 |
| `avatar_preset` | 不限制 | 限定 `cat/bunny/bear/penguin` | 防止被組成任意路徑；以後新增頭像款式時要一併改這個限制 |
| `avatar_url` | 不限制 | 只接受 `https://*.supabase.co/storage/v1/object/public/avatars/…`（01 用 `not valid`，不檢查既有資料） | 前台會把它當 `<img src>` 用 |
| 過渡期 | — | 01 會放寬 `companion_type` 的 not null | 跑完 01、還沒跑 02 的期間也能新增學生 |
| 02 | — | 包在 `begin/commit` 裡，結尾附驗證查詢 | 不會停在刪一半的狀態 |
| quiz 函式 | 待補 | `get_quiz_batch(text, int)`、`list_quiz_topics()`、`grade_quiz(jsonb)` | 依原 `schema_quiz.sql` 補齊 |

**請 Cowork 同步更新規劃書第五節**（Storage 讀取方式、頭像限制）。
