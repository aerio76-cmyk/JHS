## 2. 任務 A：家長端「資料備份」
**檔案**：新增 `js/backupLogic.js`（純函式）、`tests/backupLogic.test.js`；修改 `entry.html`（新區塊 `#/backup`）、`js/entry.js`、`css/style.css`（只作用在 backup 區塊）、`README.md`（新增「備份與還原」一節）。

**功能**
- 白名單內的家長看得到「資料備份」分頁，一般管理員也看得到。
- 三個按鈕，各下載一個檔案：
  - `jhs-backup-YYYYMMDD-HHMM.json`：完整備份，格式 `jhs-backup-1`。
  - `jhs-scores-….csv`：長表格式。
  - `jhs-rankings-….csv`。
  - CSV 是 UTF-8 加 BOM、CRLF。
- 三張表都**分頁讀到空頁才停**，而且依實際收到的列數往下讀；伺服器上限比 1000 小時也不會漏資料。
- 「從備份產生還原 SQL」：選擇 JSON 檔，網站只產生 `.sql` 檔，**不會寫入資料庫**。產生的 SQL 由使用者在 SQL Editor 手動執行。
- 「上次在這台裝置下載完整備份」：存在 localStorage，讀寫都包了 try/catch；只有 JSON 備份會更新這個時間。
- 匯出中與產生 SQL 時按鈕會鎖住；訊息走常駐的 live region；所有文字都用 textContent。
- **CSP 不需要放寬**：Blob 加 `<a download>` 不受 CSP 管控，security-auditor 也確認過。

**和 1200 規格不同的地方（請確認）**
1. **`avatar_url` 不放進備份**。原因有三：
   - 需求寫明「不得包含專案網址」，而 `avatar_url` 正是專案的 Storage 網址。
   - 頭像圖檔本來就不在備份裡。
   - 還原到別的專案時，會被 `avatar_url` 的 CHECK（寫死 project ref）擋下，導致**整份還原失敗**。

   還原時，新學生的頭像是 null，前台顯示預設頭像；**已存在的學生保留原本的頭像**，不會被舊備份蓋掉。因此 1200 要求的「來回比對 avatar_url 非 null」改成驗證這兩條規則。
2. **還原時的額外保護**：資料庫裡如果已有「同名但 id 不同」的學生（例如重建資料庫時重新建立了學生），還原 SQL 會用中文說明原因並**中止**，不會悄悄多出一位同名學生。
3. 完成驗證後的查詢**只計算備份內的學生 id**，所以在非空的資料庫上，數字也能和備份對得上。

## 5. 使用者實機驗收步驟（這些我做不到）
1. 等 `backup-export` 合併上線後，登入家長端 →「資料備份」→ 依序按三個按鈕，確認下載三個檔案。
2. 用 Excel 開兩個 CSV，確認中文沒有亂碼、欄位正確。
3. **還原測試請在測試用的 Supabase 專案做，不要在正式資料庫**：
   1. Supabase 免費方案可以有 2 個專案，再建一個測試專案。
   2. 在 SQL Editor 依序執行 `supabase/schema.sql`、`supabase/seed_data.sql`。
   3. 回家長端，用「選擇備份檔並產生 SQL」選剛才的 JSON，下載 `.sql`。
   4. 在測試專案的 SQL Editor 執行，最後一行的三個數字應該和匯出時的筆數相同。
   5. 測完可以刪除測試專案。
