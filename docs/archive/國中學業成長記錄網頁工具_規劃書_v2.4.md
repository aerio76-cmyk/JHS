## 二、定案範圍（不變）
- **主軸**：國中段考成績紀錄 + 成長分析，一律「跟自己比」，語氣正向。
- **不做**：遊戲化、手足比較、英文題庫、後端、勵志小語管理介面。新增資料表／Storage bucket：除「學習資料庫」（第九節）外不做。
- **架構**：純靜態（HTML／原生 JS／Chart.js 4.4.6／supabase-js 2.117.2）+ GitHub Pages + Supabase；CDN 皆有 SRI。
- **權限**：前台免登入唯讀；成績、排名、學生資料與頭像僅白名單管理員可寫；白名單管理僅 super_admin。
- **公開顯示**：只顯示英文名與成績／排名，不放真實姓名、學校、班級。校排名公開顯示。

## 三、功能現況與細則

### 3.1 前台
首頁（問候與小語、數字磚、學習總評、最近里程碑、校排名）、成長圖表（平均走勢、科目走勢、雷達圖、學期比較、排名反向折線）、學年地圖（18 格 1–4 級）、段考回顧 `#/exam/{g}-{s}-{e}`、歷史紀錄。

- 每張圖表下方有可展開的「看數據表」；圖表 `aria-label` 帶最新值與最高值。
- 手機學年地圖：年級在每列上方，格寬 ≥ 44 px（360 px 寬為 45.7 px）。
- 小語：每次開啟隨機一句，避開最近用過的 8 句。
- 段考短標籤：手機與緊湊處以「國一上 (1)」顯示（年級＋學期＋第幾次），完整名稱仍用於段考回顧與圖表說明。
- 校排名卡顯示最新一筆排名。
- 文案一律「與上次相差 N 分／N 名」「比上次前進 N 名」。

### 3.2 判定、總評、里程碑
- 判定沿用相對歷史：progress／stable／fluctuation／peak／insufficient_data；累積 3 筆歷史（第 4 次段考）後才出現。
- 浮點容差 EPS，平均四捨五入到 1e-6；**歷史全同分且這次同分 → 穩定發揮**。
- 里程碑（前端計算，不入庫）：踏出第一步、科目新高（同次多科合併為 1 個）、平均新高（缺科段考不給也不當基準）、連續進步（剛好達 2 次給一次，中斷後可再取得）、穩定三連（剛好達 3 次）、名次前進（只比名次數字）、學期完成、學年完成。
- 學年地圖分級：以該生所有已考次數平均做 min–max 正規化；少於 3 筆用中性底色；全同分一律第 2 級；最高格加外框與文字。
- 最亮眼科目：比上次進步最多者；第一次段考或無進步時取最高分科目。

### 3.3 家長端 `entry.html`
- **段考成績**：選學生與段考後**帶入既有分數可編輯**；欄位清空＝刪除該科（有確認視窗）；0–100、0.5 為單位；無法解析的輸入視為錯誤，不當清空；送出前再核對「畫面選擇」與「最後載入」是否同一次段考，防寫錯段考；考試日期套用整次段考。
- **校排名**：帶入既有；名次、人數為十進位整數，名次 ≤ 人數。
- **學生與頭像**：只編輯既有學生（不新增／刪除）。英文名（字母開頭，可含空白與 . ' -，最多 20 字）；主題色限 6 個色票，**沒點色票就不寫回**（避免洗掉資料庫中色票外的顏色）；預設頭像 4 款（cat／bunny／bear／penguin）。
- **上傳頭像**：原始檔 ≤ 10 MB（jpeg／png／webp）→ 置中裁正方形 → 縮至 512 px → 重新編碼 webp → 覆蓋 `avatars/{id}.webp`，`avatar_url` 帶 `?v=時間戳`；資料列更新成功後才刪舊副檔名檔案；更新失敗則刪除剛上傳的新檔。
  - 刻意設計：瀏覽器不支援 webp 編碼時（主要是舊版 Safari）改存 `.jpg`；小於 512 px 的圖不放大。
- **恢復預設**：`avatar_url` 設 null，並移除 `{id}.webp`／`{id}.jpg`。
- **登入體驗**：登入固定帶 `prompt=select_account`（可切換 Google 帳號）；OAuth 失敗會被解析並顯示中文提示（含「非白名單帳號」的說明畫面）；家長端各頁有返回按鈕；iPhone Safari 從 Google 返回後登入按鈕不會卡住（已實機驗證）。
- **白名單**（super_admin）：email 一律以文字顯示、新增時轉小寫、重複新增有提示；一般管理員看不到此區塊。
- UPDATE／DELETE 被 RLS 擋下時不會報錯、只影響 0 筆；前端以 `.select()` 檢查筆數，0 筆就顯示「沒有寫入權限」。
- 可及性：常駐 live region、`aria-invalid`／`aria-describedby`、儲存中表單 `inert`。
- **資料備份**（`#/backup`，登入且在白名單內才看得到）：
  - 三個按鈕，各下載一個檔：完整備份 `jhs-backup-YYYYMMDD-HHMM.json`（格式 `jhs-backup-1`）、成績 CSV、校排名 CSV。CSV 為 UTF-8 含 BOM、CRLF，中文可被 Excel 正確開啟。備份內容為 `students`、`exam_scores`、`exam_rankings`，不含任何憑證或專案網址。
  - 讀取一律分頁、讀到空頁才停，不依賴 1000 列上限。
  - **`avatar_url` 不放進備份**（避免專案網址外洩，且還原到別的專案時會被 CHECK 擋下）。還原後：新學生顯示預設頭像；資料庫已存在的學生保留原頭像，不被舊備份覆蓋。頭像圖檔不在備份內。
  - 「從備份產生還原 SQL」：選 JSON 檔，網站只產生 `.sql` 檔供使用者手動在 Supabase SQL Editor 執行，**網站不寫入資料庫**。產生前會驗證備份結構；資料庫已有「同名但 id 不同」的學生時，還原 SQL 會中止並說明原因，不會多出同名學生。備份檔內容會先經過嚴格檢查，不符合格式就停止。
  - 畫面顯示「上次在這台裝置下載完整備份」的時間（`localStorage`，僅 JSON 備份會更新；讀不到就不顯示）。
  - 驗證：PGlite 來回測試 18/18（空庫還原、重複還原、改壞後覆蓋還原）；安全稽核以 20 種竄改備份測試，修正後全部被拒絕或只產生預期語句；CSV 開頭 BOM 與 UTF-8 解碼已驗證，**尚未用 Excel 實際開啟**。

### 3.4 資料庫與安全強化（已在 Supabase 執行）
- 表：`students`、`subjects`、`exam_scores`、`exam_rankings`、`motivational_quotes`（32 筆內建）、`admins`；RLS 全開。
- `supabase/patches/2026-10-19_security_hardening.sql`：
  - 白名單判斷改用 **Google 身分的 email**（`auth.identities`，經 security definer 函式 `my_google_email()`），不信任可自行修改的帳號 email。
  - `admins` 僅能新增／刪除 `role='admin'`；email 必須小寫。
  - `students.name` 限英文名格式；`students.avatar_url` 限本專案 `avatars/{uuid}.(webp|jpg)(?v=數字)`。
  - 執行前有安全檢查：super_admin 沒有對應 Google 身分時自動中止。PGlite 實測 20/20。
- Storage `avatars`：2 MB、jpeg／png／webp；寫入／更新／刪除／列出僅白名單；前台只用 `getPublicUrl()`。
- 前端：兩頁 CSP meta（script-src 鎖到精確路徑，無 `'unsafe-inline'`）、CDN SRI、supabase-js PKCE、`redirectTo` 只帶 origin + pathname。
- keep-alive workflow（在 `main`）：每 3 天唯讀查詢 `subjects`；checkout 鎖定 commit SHA（v7.0.1）、`persist-credentials: false`。
- 上線後匿名驗證已通過：列出 avatars 回空、匿名寫成績得到 RLS 42501、匿名讀 `admins` 回空；Console 無 CSP／SRI 錯誤。
- 版控：此 repo 之後的 commit 作者用 GitHub noreply email（先前 16 個 commit 不改寫）。

## 四、營運須知

**建議設定（Supabase Authentication）**：Email 確認與 Email 變更確認保持開啟；Redirect URLs 只放精確網址（正式站 `entry.html`；若要本機測試登入再加 `http://127.0.0.1:8765/entry.html`）。

**新增第二位管理員（完整步驟）**
1. 網站家長端「白名單」新增對方 email。
2. Google Cloud → OAuth 同意畫面 → 目標對象 → **測試使用者**加入對方（測試狀態上限 100 位）。
3. Supabase 暫時允許註冊 → 請對方用 Google 登入一次 → 在 Authentication → Users 確認對方出現 → 立刻恢復關閉。（開放期間陌生人即使註冊也沒有寫入權限，因白名單比對的是 Google 身分。）

**其他**
- Google OAuth 用戶端閒置 6 個月會被自動刪除；家長每次段考都會登入，不會碰到。
- keep-alive 排程：公開 repo 連續 60 天無 commit，GitHub 會停用排程（停用前寄信）；Supabase 若再次暫停，先到 Dashboard 恢復。
- 同一 GitHub 帳號底下的 Pages 共用 origin：該帳號底下不要放不信任的頁面；長期可改用自訂網域。
- `supabase/rebuild.local.sql` 只在本機（含白名單 email、被 gitignore 排除），不進版控。
- `schema.sql` 只能用在**全新專案**：檔首有防重複保護，偵測到本專案資料表或權限函式已存在就中止（訊息為中文）；既有專案只執行 `supabase/patches/` 內的檔案。安全 patch 寫死本專案 ref，日後若併回 `schema.sql` 需把 ref 參數化。

**備份習慣（免費方案沒有自動備份，這是唯一的資料保險）**
- 建議每次輸入完一批成績後下載一次完整備份（JSON），至少每學期一次；放在你自己的裝置或雲端硬碟，不要放進公開 repo。
- **只使用自己下載的備份檔來產生還原 SQL**；不要用來路不明的備份檔。
- 還原一律由你在 Supabase SQL Editor 手動執行。第一次請在**測試用的 Supabase 專案**走完整流程，確認還原有效，之後才算有備份（免費方案可建立的專案數量以你帳號顯示為準）。
- 還原後頭像：到家長端重新上傳，或使用預設頭像。

**實機驗收**
1. ✅ 登入家長端 →「資料備份」→ 依序下載三個檔案；用 Excel 開兩個 CSV，中文正常（已完成）。
2. ⏳ **還原流程**：先建立一個**新的測試用 Supabase 專案，名稱不要與正式專案相同**（例如 `JHS-test`）。⚠ 後台的 `main PRODUCTION` 標籤是每個專案預設分支的名稱，**不能用來分辨正式或測試**；執行任何 SQL 前，先確認畫面左上角的專案名稱是測試專案。依序執行 `schema.sql`、`seed_data.sql`、`supabase/patches/` 內的安全 patch，再貼上還原 SQL，確認末尾三個筆數與匯出時一致；測完可刪除測試專案。
3. ⏳ **`schema.sql` 連跑兩次**（在上述測試專案）：第二次應被中止並顯示中文訊息；之後若出現 `current transaction is aborted`，先執行 `rollback;` 再執行 `select 1;` 確認連線正常。
4. ✅ 真實 Google 登入（非白名單帳號）提示畫面、iPhone Safari 返回不卡住（已通過）。

## 九、新功能規劃：學習資料庫（2026-11-07 決定，尚未開發）

### 9.1 目的與使用情境
家長把網路上找到、對學習有幫助的**圖片**（預估 200–300 張，來源多為網頁下載）依國中科目整理成資料夾；孩子登入後可瀏覽與放大查看。內容屬暫存性質：學會了或有更好的版本就汰除或更新。

### 9.2 使用者已決定
| 項目 | 決定 |
|---|---|
| 檢視方式 | **登入後才能看**（孩子用 Google 登入）；圖片放私有儲存，不公開 |
| 範圍 | **共用資料庫**（不分學生） |
| 頂層分類 | 國文、英文、數學、自然、社會、其他（固定六類，手繪圖示，風格同本站珊瑚橘筆記本） |
| 預設子資料夾 | 自然：理化／生物／地球科學；社會：歷史／地理／公民 |
| 備份 | **整個學習資料庫（含資料夾結構）不備份**，不納入匯出與還原 |
| 「已學會」標記 | **僅家長（管理員）可標**；孩子唯讀 |
| 其餘 | 依 Cowork 建議（見下） |

### 9.3 功能規格（依建議定案）
**資料夾**
- 頂層六類固定，不可刪除、不可改名；自然、社會的預設子資料夾由 SQL 種子建立（可刪可改）。
- 家長可在頂層之下自訂**最多兩層**資料夾（總深度 ≤ 3），新增／改名／刪除。刪除非空資料夾須確認並說明會連同其中圖片一起刪除。
- 可選：圖片附年級標籤（國一／二／三），不強制。

**圖片（家長端）**
- 上傳：多檔拖放、點選多選、貼上剪貼簿圖片；支援 jpeg／png／webp（gif 之類不收）。
- **前端處理（沿用現有頭像上傳的 Canvas 技術，不引入函式庫）**：長邊縮至約 1600 px、重新編碼 webp（不支援時 jpg 後備）、另產 ~320 px 縮圖、重新編碼即移除 EXIF（含 GPS）。單檔原始上限 10 MB；單張壓縮後目標 ≤ 400 KB，全庫以 300 張估約 120 MB（免費額度 1 GB）。
- 標題可編輯（預設取檔名）；可移動到其他資料夾；**換圖**（保留標題與位置，覆蓋檔案）；**已學會**切換（封存，預設隱藏於孩子端，家長端可篩選並還原）；**永久刪除**（刪資料列與兩個檔案，須確認）。
- 批次上傳需顯示進度與逐檔失敗原因；失敗不留下孤兒檔案（資料列寫入失敗則刪除剛上傳的檔案，沿用頭像的補償邏輯）。

**孩子端（檢視者）**
- 登入後進入 `materials.html`：六類大圖示 → 資料夾 → 縮圖格；點圖放大（lightbox，上一張／下一張、鍵盤左右鍵與 Esc、手機滑動）；標題搜尋；「最近新增」區；已封存者不顯示。
- 全程唯讀；不顯示任何管理或標記控制項。

**家長端**
- 在 `entry.html` 增加「學習資料」管理區（沿用 hash 切換）。

### 9.4 技術設計（供 Claude Code 評估後以交接檔回報調整）
- **權限**：新增 `viewers` 白名單表（email，小寫）與函式 `is_viewer_or_admin()`（同 `my_google_email()` 思路：用 `auth.identities` 的 Google email，security definer、`set search_path = ''`）。**不可重用 `is_admin()`**，因為任何在 `admins` 的人都有寫入權限。家長端新增「檢視者名單」管理（僅 super_admin，沿用白名單的 UI 與驗證規則）。
- **資料表**（新增，需 RLS 全開）：`material_folders`（id、parent_id、name、sort、is_system、created_at）、`materials`（id、folder_id、title、grade_tag、storage_path、thumb_path、is_learned、created_at、updated_at）。檢視者／管理員可 SELECT；寫入僅管理員。名稱長度、深度、`parent_id` 不得成環須有約束。
- **儲存**：新增**私有** bucket `materials`（非公開）；路徑 `{materialId}.webp`、`{materialId}_t.webp`；孩子端以 `createSignedUrls`（批次）取得短效網址，網址有效期建議 1 小時；單檔大小與 MIME 於 bucket 層限制（jpeg／png／webp，~1 MB 上限）。
- **前端**：新頁 `materials.html`（與 `entry.html` 同風格 CSP、SRI、PKCE）；CSP 的 `img-src` 需評估是否要加 Supabase Storage 網域（只加專案精確網域，不可寬鬆放行）；任何放寬需停下回報。
- **用量**：免費方案儲存 1 GB、每月流量 5 GB（另有 5 GB 快取流量）；**沒有圖片轉換服務**，縮圖必須在前端產生；格子頁只載縮圖、放大才載原圖，並用 lazy loading。
- **部署**：`materials.html` 的網址需加入 Supabase Redirect URLs（使用者手動）；檢視者上線前需加入 Google Cloud OAuth 的測試使用者並依第四節流程完成首次登入。

### 9.5 開放問題（開工前須解決）
1. **孩子是否有個人 Google 帳號？** 學校配發的帳號常封鎖第三方 OAuth，可能無法登入。若沒有可用帳號，備案為「僅家長登入檢視」（原選項 C），孩子在家長登入的裝置上看。
2. 孩子主要用什麼裝置看（手機／平板／電腦）？影響 lightbox 手勢與縮圖大小。
3. 測試使用者上限 100 位，遠低於上限；但每新增一位檢視者仍須走第四節三步驟。

### 9.6 風險
| 風險 | 對策 |
|---|---|
| **圖片多為網路下載，著作權** | 只放私有儲存、僅限家人登入檢視，不公開；本文件與 repo 不放任何內容圖片；日後不得改為公開 |
| 免費額度（1 GB／5 GB 流量） | 前端壓縮 + 縮圖 + lazy loading；顯示目前張數；300 張約 120 MB，餘裕充足 |
| 檢視者權限誤放寬 | 獨立 `viewers` 表 + 專屬函式；PGlite 測試匿名、檢視者、管理員三種角色對兩表與 bucket 的讀寫矩陣；security-auditor 必審 |
| 孤兒檔案（資料列與檔案不同步） | 上傳、換圖、刪除皆有補償邏輯並以測試覆蓋 |
| 簽名網址外流 | 短效；網址不寫入頁面以外的地方；不在 console 輸出 |
| 無備份而遺失 | 使用者已決定接受（暫存性質）；README 與畫面說明「學習資料不在備份內」 |
