- **主軸**：國中段考成績紀錄 + 成長分析，一律「跟自己比」，語氣正向。
- **不做**：遊戲化、手足比較、英文題庫、後端、勵志小語管理介面。新增資料表／Storage bucket：除「學習資料庫」（第九節）外不做。

- **架構**：純靜態（HTML／原生 JS／Chart.js 4.4.6／supabase-js 2.117.2）+ GitHub Pages + Supabase；CDN 皆有 SRI。

## 三、功能現況與細則

### 3.1 前台
首頁（問候與小語、數字磚、學習總評、最近里程碑、校排名）、成長圖表（平均走勢、科目走勢、雷達圖、學期比較、排名反向折線）、學年地圖（18 格 1–4 級）、段考回顧 `#/exam/{g}-{s}-{e}`、歷史紀錄。

- 每張圖表下方有可展開的「看數據表」；圖表 `aria-label` 帶最新值與最高值。
- 手機學年地圖：年級在每列上方，格寬 ≥ 44 px（360 px 寬為 45.7 px）。
- 小語：每次開啟隨機一句，避開最近用過的 8 句。
- 段考短標籤：手機與緊湊處以「國一上 (1)」顯示（年級＋學期＋第幾次），完整名稱仍用於段考回顧與圖表說明。
- 校排名卡顯示最新一筆排名。
- 文案一律「與上次相差 N 分／N 名」「比上次前進 N 名」。

### 3.2 判定、總評、里程碑
- 判定沿用相對歷史：progress／stable／fluctuation／peak／insufficient_data；累積 3 筆歷史（第 4 次段考）後才出現。
- 浮點容差 EPS，平均四捨五入到 1e-6；**歷史全同分且這次同分 → 穩定發揮**。
- 里程碑（前端計算，不入庫）：踏出第一步、科目新高（同次多科合併為 1 個）、平均新高（缺科段考不給也不當基準）、連續進步（剛好達 2 次給一次，中斷後可再取得）、穩定三連（剛好達 3 次）、名次前進（只比名次數字）、學期完成、學年完成。
- 學年地圖分級：以該生所有已考次數平均做 min–max 正規化；少於 3 筆用中性底色；全同分一律第 2 級；最高格加外框與文字。
- 最亮眼科目：比上次進步最多者；第一次段考或無進步時取最高分科目。

### 3.3 家長端 `entry.html`
- **段考成績**：選學生與段考後**帶入既有分數可編輯**；欄位清空＝刪除該科（有確認視窗）；0–100、0.5 為單位；無法解析的輸入視為錯誤，不當清空；送出前再核對「畫面選擇」與「最後載入」是否同一次段考，防寫錯段考；考試日期套用整次段考。
- **校排名**：帶入既有；名次、人數為十進位整數，名次 ≤ 人數。
- **學生與頭像**：只編輯既有學生（不新增／刪除）。英文名（字母開頭，可含空白與 . ' -，最多 20 字）；主題色限 6 個色票，**沒點色票就不寫回**（避免洗掉資料庫中色票外的顏色）；預設頭像 4 款（cat／bunny／bear／penguin）。
- **上傳頭像**：原始檔 ≤ 10 MB（jpeg／png／webp）→ 置中裁正方形 → 縮至 512 px → 重新編碼 webp → 覆蓋 `avatars/{id}.webp`，`avatar_url` 帶 `?v=時間戳`；資料列更新成功後才刪舊副檔名檔案；更新失敗則刪除剛上傳的新檔。
  - 刻意設計：瀏覽器不支援 webp 編碼時（主要是舊版 Safari）改存 `.jpg`；小於 512 px 的圖不放大。
- **恢復預設**：`avatar_url` 設 null，並移除 `{id}.webp`／`{id}.jpg`。
- **登入體驗**：登入固定帶 `prompt=select_account`（可切換 Google 帳號）；OAuth 失敗會被解析並顯示中文提示（含「非白名單帳號」的說明畫面）；家長端各頁有返回按鈕；iPhone Safari 從 Google 返回後登入按鈕不會卡住（已實機驗證）。
- **白名單**（super_admin）：email 一律以文字顯示、新增時轉小寫、重複新增有提示；一般管理員看不到此區塊。
- UPDATE／DELETE 被 RLS 擋下時不會報錯、只影響 0 筆；前端以 `.select()` 檢查筆數，0 筆就顯示「沒有寫入權限」。
- 可及性：常駐 live region、`aria-invalid`／`aria-describedby`、儲存中表單 `inert`。
- **資料備份**（`#/backup`，登入且在白名單內才看得到）：
  - 三個按鈕，各下載一個檔：完整備份 `jhs-backup-YYYYMMDD-HHMM.json`（格式 `jhs-backup-1`）、成績 CSV、校排名 CSV。CSV 為 UTF-8 含 BOM、CRLF，中文可被 Excel 正確開啟。備份內容為 `students`、`exam_scores`、`exam_rankings`，不含任何憑證或專案網址。
  - 讀取一律分頁、讀到空頁才停，不依賴 1000 列上限。
  - **`avatar_url` 不放進備份**（避免專案網址外洩，且還原到別的專案時會被 CHECK 擋下）。還原後：新學生顯示預設頭像；資料庫已存在的學生保留原頭像，不被舊備份覆蓋。頭像圖檔不在備份內。
  - 「從備份產生還原 SQL」：選 JSON 檔，網站只產生 `.sql` 檔供使用者手動在 Supabase SQL Editor 執行，**網站不寫入資料庫**。產生前會驗證備份結構；資料庫已有「同名但 id 不同」的學生時，還原 SQL 會中止並說明原因，不會多出同名學生。備份檔內容會先經過嚴格檢查，不符合格式就停止。
  - 畫面顯示「上次在這台裝置下載完整備份」的時間（`localStorage`，僅 JSON 備份會更新；讀不到就不顯示）。
  - 驗證：PGlite 來回測試 18/18（空庫還原、重複還原、改壞後覆蓋還原）；安全稽核以 20 種竄改備份測試，修正後全部被拒絕或只產生預期語句；CSV 開頭 BOM 與 UTF-8 解碼已驗證，Excel 實際開啟中文正常（使用者已驗證）。

### 3.4 資料庫與安全強化（已在 Supabase 執行）
- 表：`students`、`subjects`、`exam_scores`、`exam_rankings`、`motivational_quotes`（32 筆內建）、`admins`；RLS 全開。
- `supabase/patches/2026-10-19_security_hardening.sql`：
  - 白名單判斷改用 **Google 身分的 email**（`auth.identities`，經 security definer 函式 `my_google_email()`），不信任可自行修改的帳號 email。
  - `admins` 僅能新增／刪除 `role='admin'`；email 必須小寫。
  - `students.name` 限英文名格式；`students.avatar_url` 限本專案 `avatars/{uuid}.(webp|jpg)(?v=數字)`。
  - 執行前有安全檢查：super_admin 沒有對應 Google 身分時自動中止。PGlite 實測 20/20。
- Storage `avatars`：2 MB、jpeg／png／webp；寫入／更新／刪除／列出僅白名單；前台只用 `getPublicUrl()`。
- 前端：兩頁 CSP meta（script-src 鎖到精確路徑，無 `'unsafe-inline'`）、CDN SRI、supabase-js PKCE、`redirectTo` 只帶 origin + pathname。
- keep-alive workflow（在 `main`）：每 3 天唯讀查詢 `subjects`；checkout 鎖定 commit SHA（v7.0.1）、`persist-credentials: false`。
- 上線後匿名驗證已通過：列出 avatars 回空、匿名寫成績得到 RLS 42501、匿名讀 `admins` 回空；Console 無 CSP／SRI 錯誤。
- 版控：此 repo 之後的 commit 作者用 GitHub noreply email（先前 16 個 commit 不改寫）。

**其他**
- Google OAuth 用戶端閒置 6 個月會被自動刪除；家長每次段考都會登入，不會碰到。
- keep-alive 排程：公開 repo 連續 60 天無 commit，GitHub 會停用排程（停用前寄信）；Supabase 若再次暫停，先到 Dashboard 恢復。
- 同一 GitHub 帳號底下的 Pages 共用 origin：該帳號底下不要放不信任的頁面；長期可改用自訂網域。
- 同一個 Supabase 專案另有其他系統的資料表與儲存空間（RLS 開啟、沒有政策，匿名與登入者都存取不到）。**不要為那些表加上「所有已登入使用者皆可讀寫」之類的政策**，否則共用密碼的觀看帳號也會拿到同樣的權限；政策應限定自己的使用者名單。長期較乾淨的做法是分到不同專案。
- 重新產生本機 rebuild 檔時，必須刪掉 `schema.sql` 裡 `@tx-begin`／`@tx-end` 兩行，否則內層 `commit` 會提早結束外層 transaction。
- `supabase/rebuild.local.sql` 只在本機（含白名單 email、被 gitignore 排除），不進版控。
- `schema.sql` 只能用在**全新專案**：檔首有防重複保護，偵測到本專案資料表或權限函式已存在就中止（訊息為中文）；既有專案只執行 `supabase/patches/` 內的檔案。安全 patch 寫死本專案 ref，日後若併回 `schema.sql` 需把 ref 參數化。

**沒有測試專案時的資料庫變更流程（2026-11-07 起）**
1. 使用者先下載完整備份。
2. Claude Code 在**單一 transaction 內試跑並 rollback**，確認 patch 可執行、既有資料筆數前後相同、沒有留下任何物件。
3. 使用者在 SQL Editor **手動正式執行**（寫入一律由使用者執行）。
4. Claude Code 以 API 做唯讀與「預期被拒」的驗證。
5. 本機 `.env.test` 內的連線設定（不進版控、`.gitignore` 已排除）用完後，請重設資料庫密碼並清空該設定；家長端網站不使用這組密碼，重設不影響網站。
- SQL 檔內**不得直接放入不可見字元**（零寬字元、行分隔符號等），一律用 `\uXXXX` 跳脫寫法；測試已加入檢查。從編輯器複製貼上可能改掉不可見字元而使正規式失效。

**備份習慣（免費方案沒有自動備份，這是唯一的資料保險）**
- 建議每次輸入完一批成績後下載一次完整備份（JSON），至少每學期一次；放在你自己的裝置或雲端硬碟，不要放進公開 repo。
- **只使用自己下載的備份檔來產生還原 SQL**；不要用來路不明的備份檔。
- 還原一律由你在 Supabase SQL Editor 手動執行。還原流程從未實測過；本專案目前**沒有第二個 Supabase 專案可當測試環境**（免費方案專案數已滿），驗證方式見下方「實機驗收」。

## 九、新功能規劃：學習資料庫（Phase 0、Phase 1 已完成）

### 9.1 目的與使用情境
家長把網路上找到、對學習有幫助的**圖片**（預估 200–300 張，來源多為網頁下載）依國中科目整理成資料夾；孩子用**平板**登入後瀏覽與放大查看。內容屬暫存性質：學會了或有更好的版本就汰除或更新。

### 9.2 使用者已決定
| 項目 | 決定 |
|---|---|
| 檢視方式 | **登入後才能看**；孩子使用一組**共用的觀看專用帳號（email＋密碼）**；圖片放私有儲存，不公開 |
| 觀看帳號 email | 不需要是真實信箱。使用者選用**不存在的網域**（沒有人能拿它註冊 Google，符合安全要求）；代價是收不到信，忘記密碼只能由家長在後台重設 |
| 圖片取得方式 | **孩子端用需登入權杖的下載（`download()` 轉 blob）**，每次請求都重新檢查權限；不使用可外流的長效簽名網址（撤銷立即生效） |
| 主要裝置 | 平板（版面與觸控以平板為準，手機寬度保留） |
| 範圍 | **共用資料庫**（不分學生） |
| 頂層分類 | 國文、英文、數學、自然、社會、其他（固定六類，`system_key` 對應圖示） |
| 分類圖示 | **風格 B：線條＋錯位色塊**（tag `phase0-materials-mockups` 內 `b-*.svg`） |
| 預設子資料夾 | 自然：理化／生物／地球科學；社會：歷史／地理／公民 |
| 圖片尺寸 | **寬度上限 1600 px、高度上限 4800 px**；bucket 單檔上限 **2 MB**；MIME 只收 **jpeg／webp**（前端一律重新編碼） |
| 備份 | **整個學習資料庫（含資料夾結構）不備份** |
| 「已學會」標記 | **僅家長可標**；孩子唯讀；**觀看帳號在資料庫層就看不到已學會的圖片** |
| `schema.sql` | 維持獨立 patch，**不併入** `schema.sql` |
| 測試依賴 | 同意新增 PGlite（僅開發測試） |
| 模擬圖 | 在 `materials-mockup` 分支，不合併進 `main`，以 tag 保存 |

### 9.3 功能規格
**資料夾**
- 頂層六類固定（`is_system`），不可刪除、不可改名；自然、社會的預設子資料夾由 SQL 種子建立（可刪可改；刪掉後重跑 patch 不會再長出來）。
- 家長可在頂層之下自訂**最多兩層**資料夾（總深度 ≤ 3）：新增、改名、刪除。**沒有「移動資料夾」功能**（`parent_id` 建立後不可改）。刪除非空資料夾的確認鈕直接寫出「刪除資料夾和 N 張圖片」，預設焦點在「取消」。
- 可選：圖片附年級標籤（國一／二／三）。

**圖片（家長端）**
- 上傳：多檔拖放、點選多選、貼上剪貼簿圖片；來源支援 jpeg／png／webp，**上傳到儲存的一律是 jpeg 或 webp**。
- **前端處理（沿用頭像上傳的 Canvas 技術，不引入函式庫）**：寬 ≤ 1600、高 ≤ 4800（小圖不放大）、重新編碼 webp（不支援時 jpg）、另產 ~320 px 縮圖；重新編碼即移除 EXIF（含 GPS）。單檔原始上限 10 MB；像素總數超過約 5000 萬的圖直接拒絕並說明原因。**一次只壓縮一張**；優先用 `createImageBitmap` 的縮放選項在解碼時縮小，用完立即 `close()` 並把 canvas 尺寸歸零。建議把頭像與學習資料的縮圖處理抽成共用函式（順便解掉 Backlog「大圖分段解碼」）。
- 標題可編輯（預設取檔名）；可移動到其他資料夾；**換圖**＝上傳到新檔名、更新資料列後再刪舊檔；**已學會**切換（家長端灰階＋標籤、可篩選還原；孩子端完全不顯示）；**永久刪除**（確認框建議「只是想先隱藏就改用已學會」）。
- 批次上傳：壓縮 1 張、上傳 2 張並行；每張順序為產生 UUID → 上傳大圖 → 上傳縮圖 → 寫資料列；縮圖失敗刪大圖，寫列失敗刪兩檔；不覆蓋既有檔案（bucket 沒有 update 政策，覆寫與 move 都會被擋）；網路錯誤可單張或全部重試，格式錯／超限不提供重試。
- 刪除資料夾：先收集檔案路徑 → 刪資料列（`on delete cascade`）→ 再刪檔案。**所有檔案刪除與孤兒清理都必須走 Storage API 的 `remove()`，不能直接用 SQL 刪 `storage.objects`。**家長端提供「清理沒有對應資料的檔案」檢查。

**孩子端（`materials.html`）**
- 觀看登入（email＋密碼，可顯示／隱藏密碼）→ 首頁（搜尋＋六類大圖示＋最近新增）→ 資料夾（麵包屑、子資料夾、縮圖格）→ 放大檢視。
- 放大檢視：平板與桌面的上一張／下一張在左右兩側，手機在下方中間；支援左右滑動、← → 鍵、Esc、雙指縮放；關閉後焦點回原縮圖。
- 圖片以 `download()` 取得後轉 blob 顯示；縮圖格 lazy loading，一次只載入畫面附近的縮圖；用完 `URL.revokeObjectURL`。
- 全程唯讀；明顯的登出鈕；不提供改密碼介面。

**家長端**
- `entry.html` 增加「學習資料」管理區（資料夾樹、批次上傳、圖片操作選單、已學會篩選、用量顯示）。手機寬度時圖片區塊排在資料夾樹前，操作選單改為底部面板。

### 9.4 技術設計（Phase 1 已實作並套用）
**權限（資料庫層強制）**
- 觀看帳號由使用者在 Supabase 後台手動建立（自動確認）；**建議設定**：網站不提供註冊；需啟用 Email 登入；「Manual linking」保持關閉；「Secure email change」開啟；最低密碼長度設長一點（例如 12 字以上）。
- `viewers(user_id → auth.users on delete cascade, label)`：RLS 開啟、沒有任何政策、不給 anon／authenticated 權限，只能在 SQL Editor 維護。trigger 擋下兩種帳號：有 Email 以外登入身分的、email 與管理員相同的。
- `is_viewer()`：必須在名單內**而且只有 Email 登入身分**；帳號一旦被連上 Google，觀看權限自動失效。
- `is_admin()`／`is_super_admin()`／`my_google_email()` 都加上「不在 viewers 名單」前置條件，所以觀看帳號即使事後被連上白名單內的 Google 身分也**不會升為管理員**。
- 孩子端查詢條件為「觀看者或管理員」；管理員在同一台裝置換登入後也能看（管理員看得到已學會圖片，孩子端查詢要自己加 `.eq('is_learned', false)`）。
- 撤銷：刪掉 `viewers` 列，下一個請求起讀不到；因為不使用簽名網址，沒有已外流的網址要擔心。

**資料表（RLS 全開，欄位權限限縮）**
- `material_folders`：`id`、`parent_id`（不可改，欄位權限＋trigger 兩層）、`name`（1–20 字，不得有前後空白、控制字元或零寬字元）、`sort`、`is_system`／`system_key`（網站不能設定）、`created_at`。同層不重名（含頂層部分索引）；深度 ≤ 3 以 insert trigger 擋。
- `materials`：`id`、`folder_id`、`title`（1–60 字）、`grade_tag`（1／2／3 或 null）、`storage_path`（`uuid.webp|jpg`）、`thumb_path`（同 uuid 加 `_t`）、`is_learned`、`created_at`、`updated_at`（trigger 維護）。
- **只能用 `insert`／`update`，不能用 `upsert`**；payload 不可帶 `is_system`、`system_key`、`created_at`、`updated_at`，`material_folders` 也不可帶 `id`。新增資料夾的 `sort` 設為同層最大值 + 1（預設子資料夾排序 1..3，自訂預設 0 會排到最前）。

**儲存**：私有 bucket `materials`，2 MB、只收 jpeg／webp；管理員可讀、上傳（檔名正規式限制）、刪除；沒有 update 政策；觀看帳號只能讀「有對應資料列且未標為已學會」的檔案（security definer 函式 `can_view_material_file()`，匿名請求與 avatars 請求不受影響）。

**前端 CSP**：`materials.html` 的 `img-src` 加 `blob:`（因改用 `download()`），其餘最小：`'self'` 加 `blob:`；`connect-src` 同 `entry.html`；不需要 Google 相關來源。任何其他放寬先停下回報。

**登入與會話**：`signInWithPassword`；`invalid_credentials` 一律顯示同一句固定中文；HTTP 429／`over_request_rate_limit` 顯示「嘗試次數太多」；不直接顯示伺服器回傳文字。同一網域共用 session：觀看帳號登入後開 `entry.html` 會看到「沒有編輯權限」（正確）；家長在同一台用 Google 登入會換掉觀看帳號。觀看帳號可自行改密碼（無法用政策擋），介面不提供。密碼自己保管，不得出現在 repo、文件、測試或 console。

**Phase 3 實作注意**

### 9.5 營運須知（學習資料庫）

| 孤兒檔案（資料列與檔案不同步） | 補償邏輯 + 清理檢查（走 Storage API）；測試覆蓋 |
